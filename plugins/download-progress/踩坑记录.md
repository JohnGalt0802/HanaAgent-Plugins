# 踩坑记录：0.679.3 插件卡片渲染机制（download-progress 案例）

日期：2026-08-21
状态：已修复 ✅

## 症状

新前端（artifact 0.679.3）下，download-progress 插件的下载进度卡片无法显示。
聊天流里出现占位壳：`WebView card 徽章 + "下载 xxx" + "正在准备下载 xxx" + Chalkboard 标签`。
真实进度条/速度/ETA 全不出来。

## 根因链（逐层实证）

### 1. 0.679.3 架构变更：plugin_card 主聊天流只占位

`SendButton-D5rPlvdg.js` 的 `Bn` 组件（plugin_card 块渲染器）**硬编码占位**：
```js
function Bn({card}) {
  return <Card title={card.title} subtitle={card.description}
    statusLabel="Chalkboard" disabled />;  // 纯静态，不渲染 iframe！
}
```
- 占位壳文案 = `title + description + "Chalkboard" 标签`
- 徽章 "WebView card" = `ui(card.type)` 函数（webview/iframe → "WebView card"）

**设计意图**：plugin surface 卡片不再内嵌主聊天 transcript，引导用户去 Chalkboard / Card Center。

### 2. 真实 iframe 渲染在 Chalkboard 卡片（Hae 组件）

`CardShell-CFI6eRQN.js` 的 `Hae`（plugin-webview 卡片）：
- 从 `pluginCards`（`/api/plugins/cards`）查卡片定义（`pluginId + cardId`）
- 找不到 → 渲染 `data-plugin-webview-unavailable="missing_card"` 占位
- 找到 → iframe 渲染 `routeUrl`（静态，无 query 参数）

### 3. 缺 contributes.cards 是致命缺口

`/api/plugins/cards` 数据源 = `pluginManager.getCards()` = `manifest.contributes.cards` 数组。
**download-progress 的 manifest.json 只有 configuration，没有 cards 声明** → cards 列表空 → Chalkboard 找不到卡片 → 永远占位。

`_loadCards` 的 schema（server bundle 实证）：
```js
const r = t.manifest?.contributes?.cards;      // 必须数组
if (t.accessLevel !== "full-access") skip;      // 需 full-access
if (!fs.existsSync(routes/)) skip;              // 需 routes/ 目录
for (const card of r) {
  const id = normalize(card.id);                 // 必须
  const type = card.type || "webview";           // 只支持 webview！
  if (type !== "webview") skip;
  const route = normalize(card.route);           // 必须 / 开头
  this._cards.push({pluginId, id, type, title, route, ...});
}
```

## 修复（三个层面）

### 修复 1：manifest.json 加 contributes.cards（必做）
```json
"contributes": {
  "cards": [{
    "id": "download",
    "type": "webview",
    "title": "下载进度",
    "description": "下载任务实时进度",
    "route": "/card/download"
  }]
}
```
效果：`/api/plugins/cards` 返回 download-progress 卡片，Chalkboard 能渲染。

### 修复 2：routes/download.js 无 taskId 自动回退（配合静态 routeUrl）
Chalkboard 卡片用**静态 routeUrl**（`/card/download` 无 taskId），打开时自动取最近任务：
```js
if (!taskId) {
  const all = [...manager.tasks.values()];
  const active = all.filter(t => t.state === "running" || t.state === "pending");
  const pick = active.length ? active[0] : all[all.length - 1];
  if (pick?.taskId) taskId = pick.taskId;
}
```
注意：`manager.tasks` 是 Map（dlcore.js 内部字段），**没有 `all()` 方法**。

### 修复 3：renderer Bn 组件内嵌 iframe（恢复老版本行为）
改 `artifacts\renderer\0.679.3\assets\SendButton-D5rPlvdg.js` 的 `Bn`：
- webview/iframe 类型 + 有 route/pluginId → 渲染 iframe（URL = baseUrl + /api/plugins/ + pluginId + route + token）
- 其他类型保留 Chalkboard 占位
- **注意**：`T(j=>...)`（useStore hook）必须在函数顶部无条件调用（React hooks 规则），不能放 if 分支里

iframe URL 用 query token（local 连接有效）：
```
{baseUrl}/api/plugins/{pluginId}{route}&token={token}
```
（card.route 自带 taskId，如 /card/download?taskId=xxx）

## 关键教训

1. **看运行版本，别信旧源码**：探索文档基于 0.351.4，实际运行 0.679.3，渲染机制完全不同。`/api/plugins/cards` 是第一信号 —— 数据源空则一切白搭。
2. **两个 artifact 目录**：`artifacts\server\0.679.3-win32-x64\desktop\dist-renderer\` 和 `artifacts\renderer\0.679.3\` 是**两套独立构建**。桌面 Electron 加载的是后者！改 CSP 改错目录白折腾一轮。
3. **minified JS 可改**：改压缩代码可行（node --check 验证语法），但 hooks 调用顺序必须保持 React 规则。
4. **升级会覆盖**：改 `artifacts\renderer\` 的 minified JS 是临时修复，Hana 升级后丢失。后续应推动官方支持聊天流内嵌 plugin 卡片。
5. **git 本地落后远端**：本地 git 仓库的 v1.6.1 是旧的，远端已有 v1.6.7（wait 轮询增强、署名 John Galt）。改代码前先 fetch/reset 到远端，再应用修改，避免用旧版本覆盖新版本。

## 追加：Clash TUN 代理环境 + 下载链路（2026-08-21 下午）

### 症状
下载测试连续失败（"网络请求失败"），但同一时刻 Invoke-WebRequest / 浏览器正常。

### 根因链
1. **Node 内建 fetch（undici）不读系统代理**（WinINET 注册表），也不读环境变量代理（除非显式 dispatcher）。
2. 用户环境开着 **Clash TUN 模式**（网卡 198.18.0.1 = Fake-IP 段 + 系统代理 127.0.0.1:7890）。
   TUN 接管后 Node 直连 TCP 可能不稳/失败，而走 WinINET 的 Invoke-WebRequest 正常。
3. 排查混淆点：exec_command 的沙箱（restricted-token runner）默认也断网 —— 测试网络前
   **必须 require_escalated 提权**，否则误判"网络坏了"（提权后 node fetch 直连是通的）。

### 修复（dlcore v0.1.6）
- 手写 HTTP CONNECT 隧道 Agent（无第三方依赖，https.Agent.createConnection 覆写）。
- 代理来源优先级：环境变量 HTTPS_PROXY/HTTP_PROXY → 插件 config.json 的 proxy 字段 → Windows 注册表系统代理。
- **代理优先 + 失败自动降级直连**：代理返回 4xx/5xx 或网络错误 → 直连重试一次。
  （实测 npmmirror 的 CDN 风控拒绝代理流量返回 400，但直连正常 —— 不能只走代理。）
- **文本重定向跟随**：npmmirror registry 对 tgz 返回 **200 + "Redirecting to <url>" 文本**（非标准 3xx），
  需要 readSmallBody（CL<4KB 缓冲）识别并跟随；缓冲数据非重定向时写回流。

### 插件模块缓存大坑（最耗时）
- **插件加载器缓存 lib 模块**（Node import cache 按 URL）。dlcore.js 改代码后，dev reset / dev reload
  **不生效**（MGR_VER 只换单例实例，不换代码！）。唯一生效方式：**重启 hana-server**。
- 验证方法：dlcore 里写 debug 日志文件（fs.appendFileSync），看文件是否生成即可判断新旧代码。

### 重启纪律
用户 2026-08-21 授权：重启前告知 + loop_control schedule 定时唤醒即可，不再逐次请示。
重启脚本：`pwsh -File D:\HanakoWorks\_tools\restart-hana\restart-hana-reliable.ps1`（杀透 6 进程，约 15-30 秒）。

## 2026-08-24 deferred 占位断链：notifyWhenDone 只 resolve 不 register（v0.5.0 已修复 ✅）

### 症状
Agent 调 `download-wait(notifyWhenDone=true)` 后收束回合，下载完成（tasks.json state=done）但**永远不唤醒**。
会话 jsonl 实锤：agent 每一步都对（22:40 调 notifyWhenDone，明确说"后台通知已注册"），23:09 下载完成，无唤醒。

### 根因（宿主 bundle 实证，v0.681.5）
- 宿主 deferred 协议：`deferred:register`（注册占位，必需 sessionId/sessionPath）→ `deferred:resolve`（按 taskId 解析投递）。
  解析时**占位不存在 → 整个分支跳过，什么都不发生**（bundle line 150171）。
- 插件 index.js 只调了 resolve（onFinal 里），**全插件 grep 不到任何 register** → 占位从未建立 → resolve 空转，
  `.catch(()=>{})` 吞掉错误，静默失败。文档/工具描述里"注册后台通知"是虚假承诺。
- 宿主 bundle 里搜不到 `notifyWhenDone` 字样：宿主不认识这个参数，不会自动注册。
- 宿主内置机制（media/subagent/workflow）全部显式调 register——第三方插件要自注册。

### 同类断链
- 停滞通知（taskId:stall）同样只 resolve 不 register → 停滞也从不投递。

### 修复（v0.5.0）
- 创建任务时自动 register（download-file/command 内调 registerDeferred），不依赖 agent。
- 终态必投递（onFinal resolve）+ onload 对遗留终态任务幂等兜底（覆盖重启缝隙）。
- onStall 动态 register+resolve taskId:stall 占位（成对完成，无幽灵）。
- 宿主无"按任务取消占位"API（只有 register/retry/resolve/fail/abort，abort 会误报中止）→ 终态必投递，
  agent 已消费时投递冗余但无害（result 带 consumedByWait 标记识别）。
- 修改需重启 hana-server 生效（lib 模块缓存，dev reload 无效）。

### 教训
1. **host 协议先摸清再写通知逻辑**：只实现 resolve 端、不实现 register 端 = 空转轮子，文档承诺的"通知"根本不落地。
2. **bus 请求的失败被 .catch 吞掉时，永远无法发现断链**——onload 兜底 + 幂等 resolve 是安全网。
3. 宿主 bundle（artifacts/server/*/bundle/index.js）可 grep 实证协议实现，minified 可读。

## 2026-08-21 v0.2.3 阶段踩坑（下载管理器/explorer/高度）

### 坑1：explorer 打开文档文件夹（execFile 转义内嵌引号）
- 现象：打开/打开文件夹按钮弹的是“文档文件夹”（explorer 默认位置），不是目标路径
- 根因：`execFile("cmd.exe", ["/c", 'explorer.exe "C:\\Users\\John Galt\\..."'])` 时，**Node 默认对含空格+内嵌引号的参数自动加引号并转义内部引号为 `\"`** → cmd 收到错乱引号 → explorer 参数被截断 → 无参启动 → 打开文档
- 修复：加 `windowsVerbatimArguments: true` → Node 不转义引号，原样传给 cmd → explorer 收到完整路径
- 教训：execFile/exec 的 args 数组在 Windows 会按 CommandLineToArgvW 自动 quoting，内嵌引号会被转义；参数含引号时用 windowsVerbatimArguments 控制

### 坑2：卡片高度“自己变高”（body.scrollHeight 被宿主 iframe 拉伸）
- 现象：点击收起/展开后一秒内正常，下一秒被撑到大高度+下方大空白
- 根因：宿主给插件 iframe 的 body/html 注入 `height:100%` → `document.body.scrollHeight` 被拉成 iframe 高度（600）→ reportSize 报 600 → 宿主设 600 → 大空白。实测 body 设 height:100% 后 bodyScrollH=1036（视口），但 `.dl` 本体 offsetHeight=45 免疫
- 修复：reportSize 用**卡片本体 `.dl` 的 offsetHeight + body padding**（任何容器 height:100% 都拉不垮它）→ 折叠 61/展开 173/收起 61 永远贴合
- 教训：宿主 iframe 高度管理会注入 height:100% 给 body；报高不能用 body.scrollHeight（被污染），要用内容容器/本体

### 坑3：manager 行菜单“打开所在文件夹”失效（closeRowMenu 清空 rowMenuTask）
- 现象：manager 卡片行菜单“打开所在文件夹/打开文件”点了没反应
- 根因：`opt.onclick = function(){ closeRowMenu(); if(rowMenuTask) reveal(rowMenuTask); }` —— **closeRowMenu() 先把 rowMenuTask 置 null** → `if(rowMenuTask)` 恒 false → reveal 永不执行
- 修复：onclick 里**先存局部变量 `var t = rowMenuTask` 再 closeRowMenu 再用 t**
- 教训：函数内先清状态再判断同一状态 = 经典 bug；先快照再清理

### 坑4：cmd /c 命令注入面（老哥复核揪出）
- 现象：explorer 参数含 `&`/`|` 时可能被 cmd 拆成多条命令（`a&calc&b.zip` → 执行 calc）
- 修复：cmd /c + 双引号 + `^` 转义 `&|^%<>"!`（命令边界/重定向/转义符/变量展开全覆盖）
- 教训：cmd 的 `&|<>^%` 是命令分隔符/元字符，路径进 cmd 必须转义或参数化；经 cmd 层必然有注入面，需专门防护

### 坑5：spawn explorer.exe 直传 exit 1（explorer 自解析参数）
- 现象：`spawn("explorer.exe", ["/select,"+path])` 返回 exit 1（explorer 无视 CommandLineToArgvW，含空格参数自解析截断）
- 修复：必须经 `cmd /c` 包引号（explorer 才收到完整路径）
- 教训：explorer.exe 是 GUI 特殊进程，spawn 直传参数会被它自解析；含空格路径必须 cmd /c + 引号

### 坑6：push 网络问题（HTTP/2 直连被拒 + 明文 token）
- 现象：git push 偶发 non-fast-forward 拒绝/认证失败/连接重置（TUN 环境）
- 根因：Clash TUN 环境 HTTP/2 POST 被干扰；git remote URL 里曾明文硬编码 token（违反安全）
- 修复：push 脚本 `-c http.proxy= -c https.proxy= -c http.version=HTTP/1.1` 直连 + 显式 refspec `refs/heads/main:refs/heads/main`；token 改运行时注入（DPAPI 解密）不入 git config
- 教训：TUN/代理环境 git push 用 HTTP/1.1 + 显式 refspec 最稳；token 绝不能硬编码进 remote URL

### 坑7：reportSize 报高几版演进（body → #dl-root → .dl）
- 演进：v0.1.x/v0.2.2 用 `body.scrollHeight`（被 height:100% 污染报 600）→ d3ff5bb 改 `#dl-root.scrollHeight`（免疫，但少 padding）→ 26a35c3 补 padding → d67494c 最终用 `.dl.offsetHeight + padding`（绝对免疫）
- 教训：报高元素选最底层卡片本体；每换一次都要实测宿主 iframe 污染场景
